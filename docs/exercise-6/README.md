# משימה 6 — שני כללים ו־Skill אחד

## מטרה ומצב

המשימה מתרגלת הוראות קבועות לפרויקט, הוראות הנטענות רק בנתיב מתאים ואריזת תהליך חוזר כ־Skill.

שני הכללים וה־Skill נוצרו ונבדקו. מסמך זה מרכז את הראיות; הוא אינו אישור שבוצע commit. להשלמת המשימה יש לשמור את הקבצים והתיעוד ב־commit.

## 1. כלל קבוע: עיבוד מקומי

קובץ: `.claude/rules/local-only.md`.

הכלל מבוסס על דרישות ה־File Browser: בזמן השימוש האפליקציה מעבדת קבצים מקומית בדפדפן, אינה מבצעת קריאות רשת, אינה משתמשת ב־localStorage או IndexedDB ואינה כותבת לקובצי המשתמש. המטרה היא לשמור את הקבצים והמידע במחשב וללא שינוי.

הקובץ ללא frontmatter, ולכן מיועד להיות always-on בפרויקט הזה. הוא אינו כלל User לכל הפרויקטים. ההוראה מבדילה במפורש בין התנהגות האפליקציה לבין עבודת הפיתוח, שמותר בה לערוך קוד, להריץ בדיקות ולכתוב תיעוד.

הוכחה: בשיחה חדשה, לפני בקשת קריאה של קובץ מקור, פלט `/context all` שהמשתמש מסר הציג:

```text
Memory files
.claude\rules\local-only.md: 128 tokens
MEMORY.md: 111 tokens
```

`lib-no-ui.md` לא הופיע בפירוט הזה. [צילום סיכום הקונטקסט בתחילת השיחה](evidence/01-context-at-start.png) מראה Memory files בסך 239 טוקנים; שמות הקבצים נמסרו בפלט הטקסטואלי לצד הצילום ואינם נראים בחיתוך הצילום עצמו.

## 2. כלל ממוקד נתיב: ליבה ללא UI

קובץ: `.claude/rules/lib-no-ui.md`.

ה־frontmatter שנבדק בקובץ:

```yaml
---
paths:
  - "src/lib/**"
---
```

הכלל אוסר על קוד הליבה לייבא React או קוד מ־`src/components/`, כדי שלא יהיה תלוי בממשק המשתמש.

### בדיקת טעינה

באותה שיחה נשלחה בקשה לקרוא רק את `src/lib/fileInfo.ts`, בלי לשנות קבצים, לקרוא קבצים נוספים או להריץ פקודות ובדיקות.

לאחר הקריאה הופיעה בפלט הכלי הודעה מפורשת:

```text
Read 1 file
Loaded .claude\rules\lib-no-ui.md
```

[צילום הודעת Loaded](evidence/03-scoped-rule-loaded.png) הוא הראיה הישירה לטעינת הכלל בעקבות קריאת קובץ תואם.

### הבדל שנצפה בתצוגת הקונטקסט

ב־`/context all` שלאחר הקריאה, Memory files נותרה 239 טוקנים, ובפלט הטקסטואלי הופיעו עדיין רק הכלל הקבוע ו־MEMORY.md. הכלל הממוקד לא נוסף לרשימה הזו. [צילום לאחר הקריאה](evidence/02-context-after-read.png).

לכן המסקנה נשענת על הודעת Loaded, ולא על הופעה ברשימת Memory files. לא אומתה הסיבה להבדל התצוגה.

## 3. Skill לתהליך חוזר

קובץ: `.claude/skills/verify-feature/SKILL.md`.

שם: `verify-feature`.

מטרה: בדיקת פיצ׳ר והערכת מוכנות ל־commit. זהו תהליך שחזר במהלך משימות 2–4.

ה־Skill כולל frontmatter עם name ו־description. ההוראות מנחות לזהות את היקף העבודה, לבדוק את מצב Git וההבדלים, להריץ `npm run check`, להציע בדיקות ידניות מתאימות ומקרי גבול, להפריד בין מה שנבדק לבין מה שעדיין ממתין ולסכם ראיות חסרות.

גבולות: אין לערוך קוד, בדיקות או הגדרות, אין לבצע stage, commit או push, ובכשל בדיקות יש לדווח ולהמתין. אלה הוראות ל־Claude; לא נוספה אכיפה טכנית נפרדת באמצעות הרשאות או hooks.

קובץ ה־Skill נקרא ישירות ונמצא שלם. הקיטועים בפלט שהועתק לשיחה לא היו קיטועים בקובץ עצמו.

### הופעה ברשימה

המשתמש הפעיל `/skills` וסינן לפי `verify-feature`. [צילום הרשימה](evidence/04-skill-listed.png) מראה את ה־Skill בקבוצת project, כ־70 טוקנים לתיאור.

### הפעלה מפורשת

המשתמש דיווח שהפעיל:

```text
/verify-feature בדוק את פיצ׳ר Large file הקיים, בלי לשנות קבצים ובלי לבצע commit.
```

בתמליל שנמסר הופיע `1 skill available` ולאחריו דיווח על שלוש פקודות shell. לא צורף צילום של הפעלה זו; התוצאות הבאות מבוססות על הפלט הטקסטואלי שהמשתמש העתיק משיחת Claude.

תוצאות ההפעלה:
- זוהה שהפיצ׳ר כבר שמור ב־commit `61402f1`, ואין שינויי קוד ממתינים עבורו.
- נבדקו מצב Git, ההבדלים והקוד הרלוונטי.
- `npm run check` עברה: typecheck, lint ו־48 בדיקות ב־4 קבצים.
- הוצעו בדיקות ידניות, לרבות מקרי גבול סביב סף 10,485,760 בתים.
- נאמר במפורש שהבדיקות הידניות לא בוצעו בשיחה הזאת.
- צוין שקיימים בתיעוד משימה 4 צילומים קודמים, אך הם לא נפתחו באותה הפעלה.
- לפי הדיווח, לא שונו קבצים ולא בוצע commit.

הבדיקות הידניות של משימה 4 אינן נמחקות בשל כך: הן מתועדות שם. אין להציג אותן כבדיקות שבוצעו מחדש בהפעלת ה־Skill. גם אין לטעון שנבדקו מקרי הקצה הנוספים שרק הוצעו.

## ראיות ופרטיות

ארבעת הצילומים המקוריים נשמרו כאן ללא שינוי. מופיעים בהם פרטי סביבת פיתוח כגון גרסת Claude Code, מודל, סוג מנוי ונתיב פרויקט מקוצר. צילום טעינת הכלל מציג גם את בקשת הבדיקה ותשובת Claude. לפני פרסום במאגר ציבורי יש לבדוק אם פרטים אלה מתאימים לפרסום; לא בוצע טשטוש במסגרת הכנת המסמך.
