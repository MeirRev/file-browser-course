# משימה 7 — עובדה שנשמרת בזיכרון אוטומטי

## ההעדפה שנבחרה

המשתמש מעדיף הדרכה בפעולה אחת עם תוצאה שאפשר לבדוק, והמתנה לתגובתו לפני ההתקדמות. אפשר לכלול כמה לחיצות קצרות שנחוצות לאותה פעולה. בשאלה יש להסביר בלי לעבור לשלב הבא; בקשה מפורשת לתוכנית מלאה או לכמה צעדים גוברת על העדפת ברירת המחדל.

זו העדפת הדרכה אישית המשויכת לזיכרון הפרויקט, ולא שינוי בהתנהגות אפליקציית File Browser.

## בקשת השמירה

```text
שמור בזיכרון הפרויקט את העדפת ההדרכה שלי:

בהדרכה, תן בכל פעם פעולה אחת עם תוצאה שאפשר לבדוק, והמתן לתגובתי לפני המעבר הלאה. אפשר לכלול כמה לחיצות קצרות שנחוצות לאותה פעולה. כשאני שואל שאלה, הסבר בלי להתקדם לשלב הבא. אם אבקש במפורש תוכנית מלאה או כמה צעדים יחד, פעל בהתאם.

לאחר השמירה הצג את הנתיב ואת התוכן שנכתב בפועל, בלי לשנות זיכרונות אחרים.
```

המשתמש מסר את תשובת Claude שלפיה נוצר זיכרון חדש ונוספה שורה לאינדקס, בלי לשנות את שני הזיכרונות הקיימים. תמליל השמירה שהועתק היה מקוטע בחלקו. בהכנת תיעוד זה נקראו הקבצים עצמם ואומתו תוכנם המלא והשורה באינדקס.

## מה נכתב בפועל

תיקיית הזיכרון האישית של הפרויקט:

```text
~/.claude/projects/C--Users-wwwme-Desktop-file-browser/memory/
```

ב־MEMORY.md נמצאה השורה:

```markdown
- [One guidance step at a time](guidance-one-step-at-a-time.md) — one checkable action per message, wait for reply; questions get explanations only
```

הקובץ המפורט הוא `guidance-one-step-at-a-time.md`. תוכן ההעדפה בו:

```text
When guiding the user through a task, give one action at a time. Each action should have a result they can check. It may include a few short clicks needed for that one action. Wait for their reply before moving on. When they ask a question, explain without advancing to the next step. If they explicitly ask for a full plan or several steps at once, do that instead.

Why: The user stated this as their preferred way to be guided.

How to apply: Applies to any walkthrough where the user performs the steps themselves, such as UI clicks, terminal commands or screenshots for course exercises. Answer the question in the same Hebrew RTL format as other replies ([[hebrew-rtl-replies]]).
```

זהו קטע מתוכן הקובץ ולא העתק מלא של קובץ הזיכרון: לא הועתק ה־frontmatter, הכולל גם מטא־דאטה ומזהה שיחה אישית. קובצי הזיכרון המקוריים נשארו מחוץ למאגר ולא נוספו לתיעוד כקבצים פעילים.

## בדיקה בשיחה חדשה

לאחר הנחיה לצאת באמצעות `/exit` ולהפעיל `claude` מחדש באותה תיקיית פרויקט, המשתמש מסר צילום של הבקשה והתשובה. הבקשה הייתה:

```text
אני רוצה לבדוק שהאפליקציה עובדת בדפדפן. תנחה אותי.
```

הבקשה אינה מזכירה את הזיכרון או את ההעדפה להתקדמות בצעד אחד.

[צילום התשובה](evidence/01-guidance-response.png) מראה ש־Claude:
- פתח ב״נתחיל. שלב ראשון: הפעלת שרת הפיתוח.״
- ביקש להריץ `npm run dev` בטרמינל בתיקיית הפרויקט.
- הסביר כיצד לזהות את כתובת Local בפלט.
- סיים בבקשה לדווח מה הופיע, ורק אז לעבור לשלב הבא.

לכן התגובה תואמת להעדפה השמורה: פעולה אחת עם תוצאה הניתנת לבדיקה והמתנה למשתמש.

### גבולות הראיה

הצילום מראה את הבקשה ואת ההתנהגות בתשובה. הוא אינו מציג תהליך פתיחת שיחה חדשה, מזהה שיחה או אירוע טעינה של הזיכרון. אין בו הוכחה סיבתית בלעדית שהזיכרון הוא שגרם להתנהגות; זו תצפית התואמת את ההעדפה לאחר תהליך הבדיקה שהמשתמש התבקש לבצע. לא בוצעה בדיקת השוואה עם זיכרון מושבת. אין טענה שהאפליקציה נבדקה בפועל בדפדפן כחלק מבדיקת הזיכרון.

## כמה זיכרון נטען בתחילת שיחה

לפי שקופיות 16 ו־18 במצגת הקורס, בתחילת שיחה נטענות עד 200 השורות הראשונות או 25 KB של MEMORY.md. מידע מפורט בקבצים המקושרים אינו בהכרח נטען כולו אוטומטית; האינדקס מספק תקציר והפניה לקריאה לפי הצורך.

במקרה הזה MEMORY.md מכיל שלוש שורות קצרות, והשורה החדשה עצמה כבר מתארת את ההעדפה העיקרית. מגבלת הטעינה מובאת מהמצגת ולא נמדדה בניסוי זה.

## פרטיות ומצב שמירה

הצילום נשמר ללא שינוי. הוא כולל נתיב מקומי לתיקיית הפרויקט, ולכן יש לבדוק התאמה לפני פרסום במאגר ציבורי. לא הועתקו מזהי השיחה מהזיכרון למסמך.

לא שונו קוד האפליקציה, הגדרות או זיכרונות במהלך הכנת התיעוד. לא בוצע commit. לשמירה בגיט יש לכלול רק מסמך זה ואת צילום הראיה. אין להוסיף את קובצי הזיכרון האישיים למאגר.
